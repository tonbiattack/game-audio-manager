# 常駐監視プロセスと設定永続化の設計 (Issue #20)

## 意図

GUI を閉じても、`config/games.json` に登録したアプリの出力先自動適用を継続できるようにする。GUI にはタイマーによる監視は持たせず、編集と操作に専念させる。

## 目標

- GUI とは別の**単一の常駐監視プロセス** `watch-game-output.ps1` を追加する。
- GUI からアプリ別ルール (`config/games.json`) の登録・除外、監視の開始・停止、監視状態の表示ができる。
- 監視の間隔と「GUI 起動時に監視を自動開始するか」を `config/settings.json` に永続化する。
- 既存の `games.json` スキーマと、シレン専用監視 (`watch-shiren-output.ps1`) の動作は互換を保つ。

## 非目標

- 監視ロジックの多段化・複数インスタンス対応 (常に 1 プロセス)。
- シレン専用スクリプトの書き換え・削除 (段階的移行の余地は残すが本件では触れない)。
- ウィンドウを持たない未登録アプリの自動検出・自動登録。

## 選択肢

1. GUI 内タイマーで監視する: GUI を閉じると自動適用も止まるため要件を満たさない。
2. 監視ロジックを GUI の別スレッドに置く: PowerShell の WinForms は STA でスレッド線路が難しく、GUI 終了時の後始末も複雑。
3. **独立した単一の監視プロセス** (採用): GUI のライフサイクルから独立し、再利用済みの `svcl.exe` 適用ロジックをそのまま使える。

## 構成

### 監視プロセス `watch-game-output.ps1`

- `lib/GameAudio.Watch.ps1` の汎用ロジックと `lib/GameAudio.Config.ps1` の `games.json` 読み込みを利用する。
- 毎サイクル `games.json` を読み直すため、GUI でのルール変更を監視の再起動なしに反映する。
- 二重起動は名前付きミューテックス `Local\game-audio-output-watch` で抑止する。既に動作中なら即終了する。
- 停止は名前付き AutoReset イベント `Local\game-audio-output-watch-stop` のシグナルで行い、GUI はプロセスを強制終了しない。
- 出力先の適用自体は `svcl.exe /SetAppDefault <デバイス> all <exe>` を直接呼ぶ (`set-game-output.ps1` と同じ操作)。

### 監視アルゴリズム (アプリごとの状態)

`shiren-output-watch.ps1` の状態遷移と同じ意味論を汎用化した `Update-GameAudioWatchState` を使う。

- プロセス識別子は `PID:開始時刻のTicks`。ゲームの起動・再起動で再適用する。
- 適用先デバイスは `outputDevices` の左から見て最初に接続中のもの。デバイスの再接続・切替で再適用する。
- 適用が安定している間は再適用しない。失敗時は次のサイクルで再試行する。
- `enabled: false` のゲーム、未起動のゲーム、候補デバイスが未接続の場合は待機する。

### IPC と状態表示

- 監視プロセスは各サイクルで `config/watcher-status.json` を書き込む (一時ファイル + 移動で原子的に更新)。内容は PID・開始時刻・更新時刻・間隔と、アプリごとの起動状態・適用済みデバイス・最終エラー。
- GUI は 3 秒間隔のタイマーでこのファイルを読み、状態ラベルと開始/停止ボタンの有効状態を更新する。
- 動作判定は `updatedAt` の鮮度 (間隔 x 2 + 15 秒以内) と PID の生存で行う。監視終了時は状態ファイルを削除するため GUI は即座に停止を検出できる。
- GUI を閉じても監視プロセスは継続する。GUI 起動時に状態ファイルが残っていれば再結合して表示する。

### 設定永続化

- `config/settings.json`: `watchIntervalSeconds` (1-3600、既定 5) と `autoStartWatcher` (既定 false)。GUI のチェックボックスと数値欄で変更のたびに保存する。
- 間隔は監視プロセス起動時に読み込まれるため、変更後の反映は GUI から監視を再開始したときに行う。
- `games.json` は既存スキーマのまま。GUI の「監視ルールに登録」は選択中アプリと選択中デバイスで `Set-GameAudioRule` を呼ぶ (既存ルールは選択デバイスを先頭に統合、新規はルールを追加、`games.json` が無ければ作成)。`enabled` による一時停止はファイル編集のままとする。
- GUI の「監視から除外」は `Remove-GameAudioRule` でルールを削除する。すべて削除しても `games: []` として有効とする (`Get-GameConfiguration` を空配列許容に変更)。設定ファイルなしの運用は従来どおり可能。

### ログオン時の自動開始

`Install-GameAudioManagerStartup.ps1` に `-IncludeWatcher` を追加し、`watch-game-output.ps1` を非表示で起動する `Game Audio Manager Watcher.lnk` も登録できるようにする (解除は `-Remove` で両方削除)。GUI の `autoStartWatcher` は GUI 起動経由の開始用で、スタートアップ登録と併用してもミューテックスにより二重起動しない。

## 互換性への注意

- `config/games.json` の既存エントリはそのまま監視対象になる。シレンを登録すれば汎用監視でも適用できる。
- シレン専用監視と汎用監視の同時実行は可能だが、同じゲームに異なるデバイスを割り当てると競合する。移行後はシレン専用監視の停止を推奨する。
- `svcl.exe` の競合はない (短時間のコマンド呼び出し)。

## 検証

- `lib/GameAudio.Watch.ps1` の状態遷移・ミューテックス・停止イベント・状態ファイル I/O・設定 I/O を自動テストする。
- `games.json` のルール登録・統合・除外・全削除を自動テストする。
- GUI 状態テキストの整形とスタートアップ ショートカット定義を自動テストする。
- 実機では、GUI から監視開始 → ゲーム起動・デバイス再接続で適用 → GUI・ゲイン全終了で監視継続 → GUI 再起動で状態が見えることを確認する。
